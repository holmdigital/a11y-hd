<objective>
Close the single diagnosed Phase 30 UAT gap (Test 1, severity major): the DataTable APG grid exposes multiple document Tab stops because the inner sort `<button>` in sortable headers is rendered without `tabIndex={-1}`. Every sortable column adds its own native Tab stop on top of the single roving-tabindex anchor, so the UAT story (Name + City sortable) showed "name, city then leaves the grid" instead of a single stop.

Root cause (triple-verified in the debug session): the missing `tabIndex={-1}` was *specified wrongly* by 30-CONTEXT.md D-02/D-05, which contradict the phase's own APG single-tab-stop contract and W3C APG Grid guidance (focusable widgets inside grid cells must be `tabindex=-1` and reachable via grid navigation). Keyboard sorting does NOT depend on the button being tab-focusable: D-03 already routes Enter/Space through the roving cell to `handleSort` (UAT Test 6 passed on that path). The 33-test DataTable suite missed this because it has zero `userEvent.tab()` coverage — every keyboard test uses programmatic `.focus()` then `user.keyboard(...)`, which is structurally blind to document tab-order membership.

Purpose: Restore the APG grid single-tab-stop contract and close the test blind spot so this class of regression is caught mechanically.
Output: One-line source fix + corrected doc comments, superseded CONTEXT decisions, two regression tests, patch version bump + CHANGELOG entry, full package verify exit 0.
</objective>
