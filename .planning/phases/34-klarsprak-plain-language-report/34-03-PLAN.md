<objective>
Add the `plain.*` i18n chrome namespace to all 9 engine locale files so the terminal renderer (plan 04) and the plain PDF template (plan 05) read every label, badge, opening, closing, and empty-state string through `t()` — no hardcoded Swedish in `plain-report.ts` (D-01). Swedish and English get real translations; the other 7 locales get English values verbatim (real translations are deferred per CONTEXT.md).

Per D-14 (kontextgranskning), the entire 9-file addition is ONE atomic task. `LocaleData = typeof en` means the type changes the second en.json gains new keys, and all 8 other locale files must carry the same keys in the same commit or `typecheck` and `check:types` (which runs in `prepublishOnly`) fail. The review calls this type chain the most fragile step of the phase — the build breaks here, not on å/ä/ö.

This plan is wave 1: it touches only engine locale JSON files and depends on nothing in the standards plans, so it runs in parallel with plan 01. The renderer (plan 04) depends on both this plan and plan 01.

Purpose: Landing chrome before the renderer means the renderer is written against existing keys, not invented ones.
Output: `plain.*` namespace (identical key set) added to en, sv, de, fr, es, nl, fi, dk, no locale files in a single atomic pass.
</objective>
