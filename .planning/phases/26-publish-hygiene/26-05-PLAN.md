<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local dev -> npm registry | The `prepublishOnly` hook is the last line of defense between an unfinished local state and a published artifact reaching consumers |
| package.json scripts -> shell | npm runs scripts via shell; injection from script values is the developer's responsibility |
| publint / attw devDeps -> dist content | Both tools read package.json and dist files; they do not execute user code at lint time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-05-01 | Tampering | Published tarball includes test code | mitigate | `check:no-test-leak` (Plan 26-02) in test:ci within verify within prepublishOnly |
| T-26-05-02 | Tampering | Published tarball includes Tailwind classes in styled-unified components | mitigate | `check:no-tailwind-leak` (Phase 23) in test:ci |
| T-26-05-03 | Information disclosure | dist/ contains stale/incorrect types | mitigate | `attw --pack .` validates type resolution across Node10/16/bundler modes |
| T-26-05-04 | Repudiation | Publish without verify (developer skip) | mitigate | `prepublishOnly` is automatic; bypass requires explicit `--ignore-scripts` flag which is auditable in shell history |
| T-26-05-05 | Denial of service | Dry-run consumes CI minutes | accept | Cost is bounded; verify chain finishes in &lt;120s per package |
| T-26-05-06 | Elevation of privilege | Malicious dep escalates via lifecycle | accept | publint + attw are well-established devDeps; threat model is the same as any other npm dependency |
</threat_model>
