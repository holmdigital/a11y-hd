    2. Have a JSDoc block at the top explaining: PUB-05 enforcement; scans `dist/**/*.{js,mjs}` for test-framework imports; patterns are import-statement-shaped to avoid JSDoc false-positives; reference `.planning/phases/26-publish-hygiene/26-RESEARCH.md Area 6`.

    5. Define the PATTERNS array:
       ```js
       const PATTERNS = [
         { name: 'vitest-import',          re: /from\s+['"]vitest['"]/ },
         { name: 'testing-library-import', re: /from\s+['"]@testing-library\// },
         { name: 'vi.mock call',           re: /\bvi\.mock\s*\(/ },
         { name: 'top-level describe',     re: /^\s*describe\s*\(\s*['"]/m },
         { name: 'top-level it',           re: /^\s*it\s*\(\s*['"]/m },
       ];
       ```
       Per researcher: these patterns CANNOT appear in valid JSDoc prose. Avoid bare-token `vitest` / `describe(` matchers.
    6. Walk `dist/` recursively, collecting `.js` and `.mjs` files. For each file, match each PATTERN against the content; record offenders as `{ file, pattern, snippet }`.

    8. If offenders found, print a header `[check-no-test-leak] N test-code leak(s) found in dist/:`, list each offender as `  - {file}: {pattern} — "{snippet up to 80 chars}"`, print remediation hint `Fix: check tsup.config.ts entry globs exclude *.test.* and *.stories.*.`, and exit 1.
    9. If no offenders, print `[check-no-test-leak] ok — N dist file(s) free of test-code imports.` and exit 0.
