<objective>
Migrate the components package from inline tsup CLI invocations to a `tsup.config.ts` file, configure CSS extraction (no `--inject-style`), declare `sideEffects: ["**/*.css"]`, **consolidate ALL three CSS subpath exports (`./Tabs.css`, `./Accordion.css`, `./Breadcrumbs.css`) into the exports map upfront**, and add the STY-05 regression-guard script. This is Wave 1 infrastructure — Plans 23-02, 23-03, 23-04 depend on it and run in parallel after.

**Why consolidate exports here:** The 3 Wave 2 plans all run in parallel and would otherwise each rewrite the same `package.json` `exports` map → JSON merge conflict at execution time. By doing all 3 additions in Wave 1, the Wave 2 plans only touch their own files. A consumer who deep-imports `@holmdigital/components/Tabs.css` between 23-01 landing and 23-02..04 landing will get a 404 — acceptable, because such a deep-import has no reason to exist before the migration creates the file.

**Why a CSS-layout probe:** RESEARCH.md A6 flags that tsup CSS emission may be either flat (`./dist/Tabs.css`) or nested (`./dist/Tabs/Tabs.css`). The literal exports paths depend on which layout tsup actually produces, so Task 1 runs a smoke probe (temporary `src/_smoke/Smoke.{tsx,css}` added to tsup entries, build, inspect, delete) to determine the canonical shape before writing the 3 exports entries.

Purpose: enable per-component `.css` emission alongside JS in `dist/`, ensure consumer bundlers retain CSS side-effect imports under tree-shaking, ship a build-time guard that prevents Tailwind regression, and lock in the 3 CSS subpath exports in a single atomic Wave 1 write.
